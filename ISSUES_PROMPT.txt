Clear Conversation Button Not Persisting Changes
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Issue: "Clear conversation" (×) button only clears messages from UI temporarily
- Clears messages from in-memory conversations Map ✅
- Does NOT clear messages from persistent storage (disk/database) ❌
- Messages reload when conversation is reopened (drag & drop user again) ❌

Root Cause:
- clearConversationMessages() only modifies renderer.js in-memory state
- LLM conversations reload from disk via /api/llm/conversation
- Backend calls llmService.reloadConversation() which re-parses history files
- No backend API to actually delete/clear conversation messages

Storage Locations:
1. LLM Conversations:
   - Files: ~/.subjective_chat_history/ + provider-specific dirs
   - Cursor: SQLite databases in .cursor/ and workspaceStorage/*/state.vscdb
   - Claude: JSON conversation files
   - Codex: Unknown format (TBD)
   - Loaded via: Python pipeline historyRuntime (refreshHistory())
   
2. IRC Conversations:
   - In-memory only (ephemeral, standard IRC behavior)
   - No persistence → clear works correctly ✅

Current Behavior:
1. User clicks × button
2. Frontend clears conversation.events array
3. UI shows empty transcript
4. User drags same conversation back to pane
5. Frontend calls /api/llm/conversation?target=...
6. Backend reloads from disk files
7. All messages are back!

Solutions Available:

Option A: Delete Conversation Entirely
- Use existing deleteLlmConversation API
- Marks as hidden (hiddenTargets)
- Removes from llmService.local[]
- Still doesn't delete disk files (safety by design)
- Messages return on refreshHistory() unless disk files deleted

Option B: Add "Clear Messages" Backend API ⭐ RECOMMENDED
- New endpoint: POST /api/llm/clear-conversation
- For local conversations: Delete conversation file/record
- For Cursor/Claude/Codex: Return error (read-only provider history)
- Broadcast llm-conversation-cleared event
- Frontend handles read-only gracefully

Option C: Client-Side Only (IRC Pattern)
- Only allow clearing IRC conversations
- Show error for LLM: "Provider history is read-only"
- Explain conversation is backed by Cursor/Claude/Codex files

Option D: "Hide Until Refresh" Pattern
- Current behavior with better UX
- Show indicator: "Messages hidden (will reload from history)"
- Button label: "Clear from view" instead of "Clear messages"

Files Requiring Changes:
- src/llmService.js - Add clearConversationMessages(target) method
- src/webServer.js - Add POST /api/llm/clear-conversation route
- src/main.js - Add IPC handler for Electron app
- web/webBridge.js - Add clearLlmConversation client method
- src/renderer.js - Update clearConversationMessages() to call backend
- src/renderer.js - Add UI feedback for read-only conversations

Decision Required: Which solution matches user expectations?
- Permanent deletion (irreversible)
- Temporary hide (current behavior, needs better UX)
- Hybrid (delete local, hide provider history)

Documentation: CLEAR_CHAT_ANALYSIS.md
